# 利用者向け操作マニュアル

更新日: 2026-08-31

このマニュアルは、WebAppから施設・レビュー取得を実行する利用者向けの正本です。初期移管、GitHub Secrets、開発者向け内部仕様は別文書に分け、この文書では日常操作に必要な内容を説明します。

## 1. 最初に確認すること

現在、通常運用で使用するのは次の2機能です。

| WebApp表示 | 用途 | データ取得元 |
|---|---|---|
| 施設・レビュー取得 (Google Places API) | 地域と業種から施設を探し、施設情報とPlacesレビューを保存 | Google Places API (New) |
| レビュー取得・新仕様逐次実行 | 既存の施設CSVを入力し、期間内レビューとオーナー返信を追加 | Bright Data Dataset / Web Scraper API |

「SERP API再開後」グループの3機能は削除していませんが、Bright Data側のSERPゾーン再開を確認するまでは通常実行しません。

実行前に次を確認してください。

- GitHubへログイン済みである
- `brightdata_ELT`のIssueとActionsを閲覧できる
- Privateデータリポジトリ`googlemap`を閲覧できる
- 同じ出力CSVを使う別のActionsが動いていない
- 初回または設定変更後は、少数行の入力とテスト用出力を使う
- Secrets、APIキー、PATをIssue本文へ書かない

契約・料金を確認する担当者は[`API_SERVICE_COST_GUIDE.md`](API_SERVICE_COST_GUIDE.md)を参照してください。Google MapsサブスクとBright Dataでは課金単位・取得できるレビュー内容が異なります。

## 2. WebAppは何をする画面か

WebAppはAPIをブラウザ内で直接実行する画面でも、CSVを編集・アップロードする画面でもありません。

```text
WebAppで条件とファイルを選択
  → 実行内容をプレビュー
  → GitHub Issueを作成
  → GitHub Actionsが入力を検証
  → APIを実行
  → googlemap/results/へCSVを保存
```

WebAppで選んだ値は、設定JSONの既定値をその実行だけ上書きします。CSVの中身や設定JSONそのものを変更する場合は、Privateデータリポジトリ`googlemap`側で編集します。

## 3. 基本的な実行手順

1. WebAppを開く
2. 「実行するワークフロー」を選ぶ
3. 設定プリセットを選ぶ
4. 入力ファイル、検索条件、出力ファイルを確認する
5. テストでは少数行の入力と新規出力ファイルを指定する
6. 「GitHubでIssueを作成」を押す
7. プレビューでワークフロー、入力、出力、件数、日数を確認する
8. 「GitHubでIssueを開く」を押し、GitHubでIssueを作成する
9. Actionsログから完了を待つ
10. Issueの完了コメントと`googlemap/results/`の出力CSVを確認する

オーナーまたは許可ユーザーが作成したIssueは自動実行されます。それ以外のユーザーが作成した場合は、オーナーまたは許可ユーザーがIssueへ`/承認`とコメントします。

## 4. 入力項目の意味

### 4.1 設定プリセット

業種ごとの検索キーワード、住所CSV、除外GID、入出力ファイルの既定値をまとめたものです。最初にプリセットを選び、その後で今回だけ変更したい項目を選び直します。

通常用とテスト用を間違えないでください。

- `（通常）`: 本番の住所範囲・出力先を使う
- `（テスト）`: 少数の住所とテスト用設定を使う

### 4.2 住所CSV

検索する地域を1行ずつ指定します。例えば、住所CSVの`北海道,札幌市`と検索キーワード`歯科医院`は、`北海道 札幌市 歯科医院`として検索されます。

住所行を増やすと検索範囲が広がり、APIリクエスト数、処理時間、費用も増えます。書式とエラー例は[`ADDRESS_CSV_GUIDE.md`](ADDRESS_CSV_GUIDE.md)を参照してください。

### 4.3 検索キーワード

取得する施設の主業種を1つ指定します。住所は住所CSVから追加されるため、キーワードへ都道府県や市区町村を書きません。

推奨例:

- `歯科医院`
- `老人ホーム`
- `グループホーム`
- `サービス付き高齢者向け住宅`

`-求人`などの除外語はSERP系で除外を意図した書式です。Google Places APIでは除外が保証されないため、取得結果を確認し、既知の不要施設は除外GID CSVへ追加します。

### 4.4 除外GID CSV

取得対象から外したい施設GIDを登録します。施設名ではなく、Google Maps上で施設を識別する施設GIDを使います。

すでに出力CSVへ保存済みの行を削除するファイルではありません。次回以降に同じ施設を新規取得しないための入力です。

### 4.5 施設入力CSV

Dataset逐次レビュー取得では、レビューを取得する施設一覧を選びます。施設ID、施設GID、Google Maps URL、および`skip_column`で指定する列が必要です。

入力CSVと出力レビューCSVは同じ業種の組合せを選んでください。歯科医院の施設CSVへ老人ホームのレビューCSVを組み合わせないでください。

## 5. 出力ファイルの選び方

出力ファイルの選択は、既存データへ継続追加するか、独立した新しいデータセットを作るかを決めます。

| 選択 | 使用する場面 | 保存動作 | ID採番 |
|---|---|---|---|
| 既存ファイル | 同じ業種・同じデータセットを継続更新 | 既存行と今回取得分をGIDで照合し、重複を1行にして新規分を追加 | 既存の採番に続く値 |
| 新規ファイル | テスト、別業種、別地域、独立データセット | 今回取得分だけで新しいCSVを作成し、同一実行内のGID重複を除去 | レビューIDは1、施設IDは101から |

### 5.1 既存ファイルを選んだ場合

1. 現在のCSVを読み込む
2. 施設は`施設GID`、レビューは`レビューGID`を主な照合キーにする
3. 同じGIDがあるデータは重複行として増やさない
4. 新しいGIDの行だけに既存IDの続きとなるIDを付ける
5. 既存行と新規行を合わせたCSVを同じファイル名へ保存する

画面上は「追記」ですが、内部では整合性を保つため、既存行と新規行をマージしてCSV全体を書き直す場合があります。実行中に同じCSVを手作業で編集しないでください。

Dataset逐次版では、同じレビューGIDの新しい行に値がある場合、既存のレビューIDを維持したまま空欄などを補完・更新することがあります。

### 5.2 新規ファイルを選んだ場合

既存CSVを読み込まず、新しい採番を開始します。

- 新規レビューCSV: `レビューID`を`1`から付ける
- 新規施設CSV: `施設ID`を`101`から付ける
- 同じAPI実行内で同じGIDが複数回見つかった場合は1行にする
- 一度保存した新規ファイルを次回も選ぶと、その次からは既存ファイルとして続きのIDを付ける

「新規ファイルを作成」を選んでも、入力したファイル名がすでに`googlemap/results/`に存在する場合は既存ファイルとして扱われます。完全な新規採番が必要な場合は、存在しないファイル名を指定してください。

### 5.3 IDとGIDの違い

- `施設ID`・`レビューID`: CSV内で使う連番。ファイルごとに独立している
- `施設GID`・`レビューGID`: 取得元が持つ識別子。重複照合に使用する

別々に作った新規CSVでは同じIDが別データを指すことがあります。複数CSVの照合・統合にはIDではなくGIDを使用してください。GIDを手作業で変更・削除すると、重複判定ができなくなる可能性があります。

### 5.4 主出力と増分出力

Google Places版には4つの出力があります。

| 出力 | 内容 |
|---|---|
| 施設出力CSV | 既存施設と今回の新規施設を統合した主ファイル |
| レビュー出力CSV | 既存レビューと今回の新規レビューを統合した主ファイル |
| 増分施設出力CSV | 今回新たに追加された施設だけ |
| 増分レビュー出力CSV | 今回新たに追加されたレビューだけ |

増分出力は今回分の確認・別システム連携用です。Google Places版の増分施設・増分レビューファイル名は設定プリセットごとに固定され、WebAppでは指定しません。実行のたびに今回分へ置き換わるため、履歴を残す場合は次の実行前にPrivateリポジトリ上で日付付きファイルへコピーします。

Dataset逐次版では、主出力とは別に`results/increments/reviews_increment_<run_id>.csv`が自動作成されます。これもその実行で新規追加されたレビューだけです。

### 5.5 出力ファイル名の例

```text
本番継続: dental_reviews.csv
受入テスト: client_acceptance_reviews_20260825.csv
地域テスト: dental_reviews_hokkaido_test_20260825.csv
```

英数字、ハイフン、アンダースコアを使い、末尾に`.csv`を付けます。WebAppでは`results/`が自動補完されます。

## 6. Google Places API版の操作

1. 「施設・レビュー取得 (Google Places API)」を選ぶ
2. 初回は`（テスト）`プリセットを選ぶ
3. 検索キーワード、住所CSV、除外GIDを確認する
4. テストでは施設主出力とレビュー主出力で「新規ファイルを作成」を選ぶ
5. 主出力ファイル名へ用途と実行日を付ける。増分2ファイルはプリセット固定名のため指定しない
6. Issueプレビューで検索キーワード、主出力、プリセット固定の増分出力を確認する
7. Issueを作成し、Actions完了後に主出力2ファイルと増分2ファイルを確認する

Google Places APIが返すレビューは1施設につき最大5件で、過去○日の期間指定や全件取得はできません。また、レビューのオーナー返信を返しません。レビューCSVの`オーナー返信`、関連度3列、`レビュー要約`が空欄でも正常です。列自体が欠けている場合は異常です。

本番を継続更新する場合だけ、同じ業種の既存主出力を選びます。増分出力は設定プリセットの固定名へ今回分が保存されます。WebAppで増分出力名を指定する必要はありません。

## 7. Dataset逐次レビュー取得の操作

1. 「レビュー取得・新仕様逐次実行」を選ぶ
2. 業種に合う施設入力CSVを選ぶ
3. 出力レビューCSVを選ぶ
   - 本番継続なら同じ業種の既存レビューCSV
   - テストなら新規レビューCSV
4. 初回テストは`days_back=30`、`rows_per_batch=20`程度の小規模設定にする
5. Bright Data同時処理数が`20`固定であることを確認する
6. Issueプレビューで入力CSVと出力CSVをもう一度確認する
7. Actionsの`prepare`、`run-batches`、`merge-results`を確認する

`days_back`は実行日時から過去何日分のレビューを取得するかを指定します。例えば`30`なら過去30日以内が対象です。Google Places版の1施設最大5件とは異なり、Bright Data Dataset版は対象期間内のレビューを多数取得でき、オーナー返信も取得対象です。ただしGoogle Maps側の表示状態やDataset応答により、期間内の全件取得を保証するものではありません。期間内レビューが本当に0件なら成功扱いです。スナップショット取得やダウンロードの失敗はエラーになります。

既存出力を選んだ場合はレビューGIDで照合し、既存行を残して新規レビューだけを追加します。新規出力ではレビューIDを1から採番します。

歯科医院の全件逐次処理は過去に約60時間22分かかりました。ただし134バッチすべての成功ではなく、94成功・40失敗の成功分66,358件をマージし、34,227件を新規追加できた部分完了です。現在は`500行・API 20件・1並列・待機90分`を標準とするため、全件時間は小規模実測から見積もり直します。同じ出力CSVを使う処理を同時に実行しないでください。

## 8. ActionsとIssueの確認

正常時は、対象処理と結果保存が成功し、Issueへ完了コメントが追加されます。選択していないジョブが`skipped`になるのは正常です。

確認する順番:

1. `parse-and-route`: IssueのコマンドとJSONを読み取れたか
2. `validate-request`: パス、必須値、入力ファイル、住所CSVが正しいか
3. 対象ジョブ: API認証とAPI応答が成功したか
4. `merge-results`または保存ステップ: 重複照合とCSV保存が成功したか
5. `report-completion`: Issueへ完了結果を書けたか

同じIssueを重複承認しないでください。失敗した場合は新しいIssueを作る前に、失敗ステップとエラーメッセージを確認します。

### success・partial・failedの見方

| 表示 | 意味 | 次の操作 |
|---|---|---|
| `success` | 対象範囲が完了。Datasetの正常なレビュー0件も含む | 出力CSVを確認する |
| `partial` | 成功分は保存済みだが、未処理または失敗範囲がある | 下記の方法で未完了範囲だけを再実行する |
| `failed` | 成功成果がない、または入力・認証・API開始で失敗 | エラー原因を直してから再実行する |

Google Places／SERP施設が`partial`の場合は、住所CSV、検索キーワード、出力先を変えずに同じ処理を実行します。`results/progress/`の進捗を使い、未処理住所から自動再開します。住所CSVの内容、キーワード、出力先を変えると新しい処理として最初から実行されます。

Dataset逐次レビューが`partial`の場合は、Issueコメントまたは`results/status/status_batch_<番号>.json`で失敗バッチ番号、開始行、終了行、完了APIチャンク数を確認します。`start_from_batch`へ失敗バッチ番号を指定し、連続範囲だけなら`max_batches`で範囲を限定します。離れた複数範囲は別々に実行します。自動再試行は行われません。

## 9. 出力CSVの確認

最低限、次を確認します。

- 指定したファイル名と更新時刻になっている
- 1行目がヘッダーである
- 文字化けや列ずれがない
- 新規ファイルのレビューIDが1から始まっている
- 新規施設ファイルの施設IDが101から始まっている
- 既存ファイルの既存IDが変わっていない
- 同じ施設GID・レビューGIDが重複行になっていない
- 増分ファイルには今回の新規分だけが入っている
- レビューCSVが共通15列になっている

レビューCSVの共通15列:

```text
レビューID,施設ID,施設GID,レビュワー評価,レビュワー名,レビュー日時,レビュー本文,オーナー返信,レビュー表示順位,レビュー取得ソート,関連度ランク,関連度取得ソート,関連度取得日時,レビュー要約,レビューGID
```

## 10. SERP API再開後の機能

次の3機能はWebAppに残していますが、SERPゾーン再開確認までは通常使用しません。

- レビュー取得 (Reviews)
- 施設データ取得 (Facility)
- レビュー取得・30日関連度ランク付き

再開時は1施設のsmoke test、新規テスト出力、10件、100件の順に増やします。詳しくは[`SERP_API_REACTIVATION_GUIDE.md`](SERP_API_REACTIVATION_GUIDE.md)を参照してください。

## 11. n8nを使う場合

n8nは次の2機能だけに使用します。

1. Googleログイン状態を半手動で作成・更新する
2. Google Maps画面からレビュー関連度順位を抽出する

どちらもCodexの案内と確認を受けながら実行します。Cookieやstorage_stateは認証情報なので、GitHub、Issue、チャットへ貼り付けません。詳しくは[`n8n_google_reviews_ops.md`](n8n_google_reviews_ops.md)を参照してください。

## 12. よくあるエラー

| 症状 | 確認・対応 |
|---|---|
| 住所CSVが選択肢に出ない | UTF-8、ヘッダー、住所行を確認し、「WebApp用ファイル一覧・住所CSV検証」を実行 |
| `住所CSVのヘッダーが不正です` | 1行目を`都道府県,市区町村,町域`形式にする |
| Issueを作成しても動かない | 作成者が許可ユーザーか確認し、必要なら許可ユーザーが`/承認`する |
| Private checkout/push失敗 | `PRIVATE_REPO_PAT`の対象と`Contents: Read and write`を管理者へ確認 |
| Google Places 401/403 | `GOOGLE_MAPS_API_KEY`とPlaces APIの有効状態を管理者へ確認 |
| Bright Data 401/403 | `BRIGHTDATA_API_TOKEN`を管理者へ確認 |
| `zone not found` | SERP再開前の機能を選んでいないか確認 |
| Datasetで0件 | `days_back`を30へ広げ、API成功の0件かログで確認 |
| 既存行が重複した | GID列が空・変更されていないか、同時実行がなかったか確認 |
| 新規なのにIDが1からでない | 指定したファイル名がすでに存在していないか確認。施設IDは101開始が正常 |
| 結果が保存されない | 保存・mergeステップ、PAT、同時push競合を確認 |
| WebAppが古い | Pagesのdeploy完了後、スーパーリロードまたはキャッシュ削除 |

解決しない場合は、Issue URL、Actions URL、失敗ステップ、エラーメッセージを開発担当者へ共有します。Secretsの値やPrivate CSVの内容は共有しません。

## 13. 安全な運用ルール

- 本番実行前にテスト入力・新規出力で確認する
- 同じ出力CSVへ複数Actionsを同時実行しない
- 本番CSVを手作業で編集する場合は、Actionsが停止中で復旧元があることを確認する
- GID列とID列を勝手に削除・変更しない
- 入力と出力の業種をそろえる
- 出力ファイル名へ用途と日付を付ける
- Public Actionsログへ個人情報、API応答全文、Secretsを出さない
- 長時間処理では途中成果と再開位置を確認する
