# 住所CSV・検索キーワード運用ガイド

更新日: 2026-08-25

この文書は、施設検索で使用する住所CSVと検索キーワードの役割、テンプレートの変更方法、実行前検証のエラー例を説明します。

## 1. なぜ住所CSVと検索キーワードが必要か

施設検索では、住所CSVの1行と検索キーワードを空白で結合して1つの検索条件を作ります。

```text
住所CSVの行: 北海道,札幌市,中央区
検索キーワード: 歯科医院
実際の検索条件: 北海道 札幌市 中央区 歯科医院
```

| 項目 | 決めるもの | 変更した場合 |
|---|---|---|
| 住所CSV | 検索する地域 | 検索地域、リクエスト数、処理時間、API費用が変わる |
| 検索キーワード | 探す施設の種類 | 歯科医院、老人ホームなど取得対象が変わる |
| 除外GID CSV | 再取得しない施設 | 登録した施設GIDが出力対象から除外される |
| 出力CSV | 結果の保存先 | 本番・テスト・業種別の保存先が変わる |

検索キーワードにある`-求人`などは、従来のGoogle検索・SERP系で除外を意図して付けている語です。ただし、[Google Places API (New)のText Search公式仕様](https://developers.google.com/maps/documentation/places/web-service/text-search)にはマイナス記号による除外条件の記載がないため、Places版での除外は保証されません。Places版では取得結果を確認し、既知の不要施設は除外GID CSVで除外してください。

## 2. 検索キーワードの書き方

検索キーワードは、プライベートデータリポジトリ`googlemap`の`settings/*.json`にある`query`へ記入します。WebAppはキーワードを直接入力する画面ではなく、設定JSONから作成されたプリセットを選ぶ画面です。

```json
{
  "task_name": "歯科医院（テスト）",
  "query": "歯科医院",
  "address_csv_path": "address_test.csv"
}
```

書き方の基本は次のとおりです。

1. 最初に、取得したい施設の種類を1つだけ書く
2. 都道府県・市区町村は書かない。地域は住所CSVから自動的に付く
3. `探してください`などの文章にせず、Google Mapsで検索する短い名称にする
4. 複数の単語が必要な場合は半角スペースで区切る
5. SERP系で除外を意図する語は、ハイフンの直後に空白を入れず`-求人`のように書く
6. 本番プリセットを直接変更せず、最初はテスト用設定JSON・住所CSV・出力CSVで確認する

| 目的 | 記入例 | 判定・注意点 |
|---|---|---|
| Google Places版で歯科医院を取得 | `歯科医院` | 推奨。住所はCSVから追加される |
| Google Places版で老人ホームを取得 | `老人ホーム` | 推奨。主業種を1つにする |
| SERP系で不要語の除外を意図 | `老人ホーム -求人 -不動産 -紹介センター` | `-`と除外語の間を空けない。SERP再開後に結果を確認する |
| 住所まで入力 | `北海道 札幌市 歯科医院` | 非推奨。住所CSVと重複する |
| 複数業種を混在 | `歯科医院 老人ホーム 結婚式場` | 非推奨。検索意図が曖昧になるため、設定を業種別に分ける |
| 長い文章 | `札幌市にある評判の良い歯科医院を探す` | 非推奨。評価などは取得後のデータで判断する |
| ハイフン後に空白 | `老人ホーム - 求人` | 不正な書き方。`老人ホーム -求人`にする |

実際にAPIへ渡される検索条件は、住所CSVの行を先、`query`を後にして結合した文字列です。

```text
住所CSV: 東京都,新宿区,西新宿
query: 歯科医院
APIへ渡す文字列: 東京都 新宿区 西新宿 歯科医院
```

検索キーワードを変更したら、少数行の住所CSVで施設名・業種・取得件数を確認してください。同じ住所でもキーワードが変わると検索対象が変わります。

## 3. 住所CSVを書き換えるとどうなるか

住所CSVは1データ行ずつ検索します。データ行を増やすほど検索範囲は広がりますが、最低リクエスト数、処理時間、API費用も増えます。検索結果に次ページがある場合は、1行で複数リクエストになることがあります。

| 住所CSVの例 | 検索範囲 | 特徴 |
|---|---|---|
| `北海道,札幌市` | 市単位 | リクエストを抑えやすいが、広い地域では検索漏れの可能性がある |
| `北海道,札幌市,中央区` | 区単位 | 市単位より細かく検索できる |
| `北海道,札幌市,中央区,大通西` | 町域単位 | 網羅性を上げやすいが、重複検索・時間・費用が増えやすい |

本番ファイルを直接書き換える前に、少数行のテスト用CSVを別名で作成し、出力先もテスト用ファイルにしてください。

## 4. 推奨テンプレート

新しく作る場合は、UTF-8のCSVとして次の形式を使用します。

```csv
都道府県,市区町村,町域
北海道,札幌市,中央区
東京都,新宿区,西新宿
兵庫県,西宮市,西宮北口
```

必須条件は次のとおりです。

- ファイルは`googlemap/settings/`へ保存し、拡張子を`.csv`にする
- 文字コードはUTF-8またはUTF-8 BOM付きにする
- 1行目をヘッダーにする
- 1列目を都道府県、2列目を市区町村にする
- 2行目以降に1件以上の住所を入れる
- 列数は2〜5列とし、ヘッダーより多い列をデータ行へ追加しない
- Excelの結合セル、数式、タイトル行、空の先頭行を使わない

既存ファイルの`a,b`、`a,b,c,d`、`a,b,c,d,e`ヘッダーは後方互換のため引き続き使用できます。ただし、新規ファイルには内容が分かる日本語ヘッダーを推奨します。既存の`end,end`は終了マーカーとして認識しますが、新規ファイルでは不要です。

## 5. WebAppでの使われ方

WebAppはCSVの中身を編集・アップロードする画面ではありません。プライベートリポジトリに保存済みの検証済みファイルを選び、実行内容をGitHub Issueとして作成する画面です。

1. 設定プリセットを選ぶと、検索キーワード・住所CSV・除外GID・出力先の既定値が入る
2. 住所CSVや出力先を変更すると、その項目だけ設定JSONの値を上書きする
3. Issueを作成すると、Issue内の値を検証してからGitHub Actionsが実行する
4. 実行結果はプライベートリポジトリの`results/`へ保存される

新しい住所CSVを追加した場合は、コードリポジトリのActionsから「WebApp用ファイル一覧・住所CSV検証」を実行します。正しいファイルだけがWebAppの住所CSV候補になります。

## 6. 不正テンプレートの拒否

住所CSVは次の段階で検証されます。

- ファイル一覧生成: 不正なCSVをWebAppの住所候補と設定プリセットから除外
- Issue検証: 選択された不正なCSVの実行を開始しない
- workflow検証: APIを呼ぶ前に処理を停止
- Python検証: Google Places版・Bright Data施設版の両方でAPIを呼ぶ前に停止

### エラー例

| 不正な内容 | 表示されるエラー例 | 修正方法 |
|---|---|---|
| ヘッダーなし | `住所CSVのヘッダーが不正です` | 1行目に`都道府県,市区町村`を追加する |
| `施設名,電話番号`など別用途のCSV | `住所CSVのヘッダーが不正です` | 住所入力用CSVを選び直す |
| ヘッダーだけで住所なし | `ヘッダー以外に1行以上の住所データが必要です` | 2行目以降へ住所を追加する |
| 1列目が`札幌`など都道府県でない | `都道府県が不正です` | `北海道`など正式な都道府県名にする |
| 都道府県または市区町村が空欄 | `都道府県と市区町村が必須です` | 1・2列目を入力する |
| データ行の列がヘッダーより多い | `ヘッダーより列数が多いです` | ヘッダーを追加するか余分な列を削除する |
| Shift_JIS・文字化け | `住所CSVはUTF-8で保存してください` | Excel等でCSV UTF-8として保存し直す |
| `=...`などの数式 | `数式または不正なセル値があります` | 計算結果を値として貼り付ける |

Actionsで失敗した場合は、`Validate request and dependencies`または`Validate configuration file`ステップの`住所CSV検証エラー`を確認してください。

## 7. 変更時の安全な手順

1. `googlemap/settings/address_test.csv`など既存テスト用CSVをコピーする
2. ファイル名を業種・地域が分かる名前に変更する
3. 日本語ヘッダーと少数の住所行へ書き換え、CSV UTF-8で保存する
4. プライベートリポジトリへコミットする
5. 「WebApp用ファイル一覧・住所CSV検証」を実行する
6. WebAppの住所CSV候補に表示されることを確認する
7. テスト用出力ファイルを指定して小規模実行する
8. 検索条件、取得件数、APIリクエスト数を確認してから行数を増やす
